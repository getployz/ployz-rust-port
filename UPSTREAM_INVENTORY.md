# Upstream material inventory

The authoritative inventory boundary is the complete 517-file Git tree at
`upstream/uncloud/`, whose identity is recorded in `UPSTREAM_ORACLE.md`. Nothing
from that tree is omitted. The categories below overlap intentionally where a
file has more than one role.

## Authored upstream material

| Material | Location | Accounting |
| --- | --- | --- |
| Go commands and source | `cmd/`, `internal/`, `pkg/` | 304 files across those directories; 308 Go files in the complete tree |
| Experiments | `experiment/` | 15 files, including three additional Go modules |
| Tests and fixtures | adjacent `*_test.go` files and `test/` | 61 Go test files; 24 files under `test/`, including Docker-backed e2e tests and fixtures |
| API schemas | `internal/machine/api/pb/*.proto` | 5 authored protobuf schemas |
| Scripts and developer tasks | `scripts/`, `.mise/tasks/` | 6 script files and 2 mise task files |
| CI and release configuration | `.github/workflows/`, `.goreleaser.yaml` | 3 GitHub Actions workflows plus GoReleaser configuration |
| Build and quality configuration | `Dockerfile`, `Makefile`, `mise.toml`, `.golangci.yaml`, `.mockery.yml`, `.editorconfig`, `.dockerignore` | checked in with the upstream tree |
| Documentation and design material | top-level Markdown, `misc/`, `website/docs/`, `website/blog/` | included with the upstream tree |
| Website application and assets | `website/` | 138 files, including Docusaurus, landing-page, static, image, and deployment assets |
| Licensing and repository guidance | `LICENSE`, `README.md`, `HACKING.md`, `AGENTS.md`, `CLAUDE.md` | `CLAUDE.md` is the upstream symlink to `AGENTS.md` |

## Generated material

Generated files remain part of the oracle and are not regenerated or edited in
this baseline:

- 9 protobuf outputs at `internal/machine/api/pb/*.pb.go`, generated from the
  adjacent authored schemas;
- `internal/machine/caddyconfig/mocks_test.go`, generated by mockery;
- Markdown command reference pages at `website/docs/9-cli-reference/`, generated
  by `go run ./cmd/uc docs` (the category metadata in that directory is authored
  website configuration);
- `mise.lock`, generated by mise for the pinned development tools;
- `website/package-lock.json` and `website/landing/package-lock.json`, generated
  npm dependency lockfiles;
- `website/landing/style.css`, generated by the landing package's Tailwind build
  from `website/landing/css/style.css` and carrying Tailwind's third-party MIT
  license banner;
- `internal/machine/store/db`, a checked-in SQLite database artifact rather than
  authored source. Upstream does not document how it was produced, so the
  baseline records it without guessing further provenance.

## Third-party material and references

- `internal/machine/api/vendor/google/rpc/status.proto` is the one vendored
  third-party protobuf source file in the Go tree.
- `website/landing/js/vendors/alpinejs.min.js` is a checked-in, minified
  third-party browser bundle.
- `website/landing/package.json` identifies the landing site as the Gray HTML
  template from Cruip.com, authored by Pasquale Vitiello under Cruip's terms.
  The tree also contains upstream-specific modifications, so the inventory
  records `website/landing/` as mixed-origin template material instead of
  guessing per-file authorship.
- `go.sum`, `experiment/go.sum`, `experiment/netbird-load/go.sum`, and
  `experiment/tsnet-load/go.sum` authenticate third-party Go modules; the module
  sources themselves are not vendored.
- The two npm lockfiles authenticate transitive website dependencies; no
  `node_modules` tree is checked in.
- `mise.lock` authenticates tool distributions; those tools are not checked in.
- Container images and release downloads referenced by `Dockerfile`,
  `mise.toml`, scripts, and CI are external runtime/build inputs, not authored
  source in this repository. Notable examples are the Docker-in-Docker base
  image, the UCinD image, and the Corrosion image/release.

Images, fonts, CSS, JavaScript, configuration, shell scripts, release metadata,
and other operational assets that do not fit the source/schema buckets remain
accounted for by the complete pinned Git tree.
