# Minimal Go-to-Rust port rules

The frozen Go tree is the oracle. Preserve its package layout, filenames, function boundaries, control flow, error behavior, ordering, source comments, and known limitations unless Rust makes direct transcription impossible. Rename product-facing Uncloud names to Ployz; do not otherwise redesign identifiers or behavior.

Use owned values for Go values that escape and borrows for call-scoped access. Translate interfaces to the narrowest Rust trait at the same seam. Translate goroutines to spawned tasks and channels to bounded or unbounded channels with the same capacity, send order, and wait behavior. Carry contexts as cancellation tokens, preserve child cancellation and timeouts, and ensure cancellation unblocks pending I/O. Translate `defer` with lexical guards or explicit cleanup on every exit. Use `Option` for `nil` only when `nil` differs behaviorally from an empty value; otherwise use the empty Rust value. Preserve observable ordering explicitly. Use generated protobuf types and their established generator rather than handwritten substitutes. Use process APIs directly with the same arguments, environment, working directory, output handling, and exit-error behavior. Translate streaming incrementally with the same directionality, backpressure, half-close, cancellation, and first-error ordering.

Do not clean up source behavior, introduce new abstractions, create placeholders, swallow errors, disable tests, add features, or build a custom workflow service, lifetime database, or porting framework.

For each file, one implementer ports source and adjacent tests but does not review. Designate at least Reviewer A and Reviewer B: heterogeneous agents working independently in separate fresh contexts. They receive identical ticket criteria, this guide, the exact Go/Rust/test pairs, and the diff, but no implementer rationale or other review report. Each reviewer is adversarial, assumes the port is wrong, only finds behavioral bugs or reasons it does not work, and reports file/line findings without implementing. Trial evidence records exact model assignments. A separate fixer who was not a reviewer receives every report, applies the smallest parity fixes, adds each recurring finding class to this guide, and replays that class against all three pairs. A human must approve this trial before bulk translation begins.

During review, apply these parity checks to every file in the batch:

- Wrapped errors must preserve both the Go-visible concatenated message and a traversable source chain. Error classifiers must match each Go sentinel exactly; do not broaden them to nearby platform error kinds, and test the distinct negative cases and the original error identity.
- A Go type assertion for an optional capability must become an explicit Rust capability, never a trait default that silently means “unsupported.” Production implementations and test doubles must declare the capability, and tests must not weaken identity assertions because a double cannot reproduce it.
- Audit parsing primitives rather than assuming similarly named Go and Rust parsers accept the same grammar, sign, base, overflow, or platform-width range. Map Go `int` to `isize` when its width is observable.
- Treat Go struct tags and standard encodings as behavior: preserve omitted zero values, field names, defaults on decode, and `[]byte` base64 JSON semantics.
- Preserve package boundaries and visibility. Re-export symbols at the Rust module corresponding to the Go package, keep Go-unexported helpers package-private, and do not expose Go `internal` packages outside the crate.
- Use native `Path`/`OsStr` forms for filesystem boundaries so non-UTF-8 paths accepted by Go remain representable. Tests that mutate process environment must serialize access and restore it with a panic-safe guard.
- Preserve the source's I/O shutdown mechanism: listener close must unblock accept, accepted stream types must retain half-close behavior, and concrete production TCP/Unix implementations must exist. Avoid adding cancellation-safety requirements, unreachable branches, or panics merely to satisfy Rust control flow.
